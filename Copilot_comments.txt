> +    # Truncate if output exceeds size cap

The output cap truncation currently slices to output_cap_bytes and then appends a truncation marker, which can exceed the configured cap. This defeats the purpose of the cap and can cause oversized payloads when returning results to the backend.

In worker/runner/executor.py:

> +    # Compute result SHA256 hash for audit chain
+    result_hash = hashlib.sha256(stdout_bytes).hexdigest()
+
result_hash is computed from stdout only. If stderr contains the meaningful output (or stdout is empty on failures), audit correlation becomes unreliable. Hashing stdout+stderr (+ exit code) makes the result_hash stable for both success and failure cases.
